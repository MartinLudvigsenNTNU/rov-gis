What this system does

This dashboard visualises AUV (Autonomous Underwater Vehicle) operational data collected by NTNU's LAUV fleet at Svalbard between 2017 and 2025. It lets you browse tracks on a map, filter by vehicle, year and area, download track data as CSV, and inspect fleet-wide statistics.

The five vehicles in the dataset are Fridtjof, Harald, Roald, Thor and Marie. Each carries a different sensor payload (see the Farkoster tab in the dashboard).

Data comes from raw DUNE/IMC log files (.lsf / .lsf.gz) ingested automatically into PostGIS. No real-time connection — all data is historical.

LeafletMap frontend

Raw logs are parsed by ingestion/ingest.py, which extracts GPS positions (EstimatedState), CTD values and vehicle metadata from each file. Each position becomes a row in the auv_tracks table with latitude, longitude, depth, speed, temperature, salinity, and conductivity.

GeoServer serves pre-computed views and materialized views as WFS. The Leaflet map and dashboard consume these directly — no backend API layer.

Map workflow

Layer panel (left side)

Tracks are grouped by vehicle and year. Toggle individual years or click the vehicle header to show/hide all years for that vehicle. The map loads tracks on demand — zooming in triggers higher-resolution tile requests.

Background maps

Two options: OpenStreetMap (default) and TopoSvalbard (NPI topographic map, better for fjord navigation context). TopoSvalbard uses EPSG:25833 (UTM 33N) natively.

Clicking a track

Click any coloured point to see vehicle, campaign, depth, temperature, salinity and speed at that position.

Mission clusters

At low zoom levels, missions are shown as numbered clusters. Clicking a cluster zooms to that area and breaks it into individual missions. Clicking a mission marker shows its bounding box and metadata.

Dashboard workflow

Oversikt tab

Shows fleet-wide totals (missions, sailed distance, vehicles, years), two bar charts (distance per year; dive time per vehicle), and two matrix tables (sensor × year km; vehicle × year km).

Farkoster tab

One sub-tab per vehicle. Each shows the sensor payload, four key statistics, and a mission outcome breakdown. Data is fetched live from GeoServer WFS.

Spatial search (top-right of map)

Draw a rectangle on the map, optionally set a date range, and click Search. The panel lists all missions whose tracks intersect the rectangle. You can export results as CSV.

Metric definitions

MetricDefinition
Sailed distance (green / km) Sum of step-by-step GPS distances where depth > 1 m and time between consecutive points ≤ 30 s. GPS jumps (> 50 m/s) are excluded. This is the actual underwater distance.
Sailed distance (red / km) Same calculation but without the depth filter — includes surface transits. Always ≥ green value.
Dive time (hours) Cumulative time when depth > 1 m. Computed as the sum of intervals between consecutive points (capped at 10 s per step to avoid inflating gaps). Aborted missions excluded.
Total time (hours) Wall-clock duration from first to last GPS point per mission, summed across all non-aborted missions. 24-hour gaps within a single named log are split into separate segments.
Missions (green) Count of missions where at least one point has depth > 1 m and duration > 3 min.
Missions (red) All missions including aborted (< 3 min) and surface-only ones.
Aborted mission Any mission with duration < 3 minutes. These are hidden from the map and excluded from all statistics.
vessel_transit Points where the computed speed exceeds 2.5 m/s. These are logged while the support vessel carries the AUV and are excluded from all track layers and distance calculations.

Mission status categories

Every mission (for Fridtjof, Harald, Roald, Thor, Marie) is classified by reading its LSF log file. The classification uses VehicleState, PlanControlState and EstimatedState IMC messages.

StatusMeaningHow detected
✅ success Mission completed as planned, or all deep manoeuvres were executed before the AUV surfaced. plan_progress = 100% in PlanControlState, OR max depth before PlanControl STOP > 1 m.
🌊 user_surface Operator aborted the mission at the surface before any deep diving occurred. AUV ended at depth < 0.5 m AND max depth before abort ≤ 1 m.
⚠️ user_depth_late Operator aborted while the AUV was underwater, after covering > 30% of the typical mission distance (≥ 0.55 km). Average end depth ≥ 1 m AND GPS distance ≥ 0.55 km.
⚠️ user_depth_early Operator aborted while the AUV was underwater, before covering 30% of the typical distance (< 0.55 km). Average end depth ≥ 1 m AND GPS distance < 0.55 km.
❌ technical Mission ended due to a fault: altitude error, depth limit, navigation failure, path control error, or hardware fault (e.g. leak sensor). VehicleState.op_mode = ERROR with a non-empty last_error string (excluding "got abort request").
Note: Classification is only available for Fridtjof, Harald, Roald, Thor and Marie (all IMC5 or IMC6 files processed). Marie's IMC6 files are classified using depth data only (no VehicleState available in IMC6 parser).

How spatial search works

  1. Click the Search button in the top-right panel of the map.
  2. Draw a rectangle by clicking two corners on the map.
  3. Optionally set a start and end date.
  4. Click Søk. The system queries GeoServer WFS (auv_missions layer) with a bounding-box and time filter.
  5. Results list all missions whose bounding box intersects your rectangle. Note: this is a bounding box intersection, not an exact track intersection — missions with wide bounding boxes may appear even if the actual track barely enters your rectangle.

The result table shows mission name, vehicle, year, and campaign. Click a row to zoom to that mission on the map.

Export workflow

After running a spatial search, click Last ned CSV to download the result list as a comma-separated file. Each row contains mission name, vehicle, year, campaign, start time, and end time.

To export raw GPS tracks for a specific mission, use the GeoServer WFS endpoint directly:

GET /geoserver/NTNU/wfs?SERVICE=WFS&VERSION=2.0.0&REQUEST=GetFeature&TYPENAMES=NTNU:auv_fridtjof&CQL_FILTER=name='<mission_name>'&outputFormat=application/json

Replace auv_fridtjof with the relevant vehicle layer name.

Known caveats and limitations

GPS jumps: Some missions contain single-point GPS errors that place the AUV hundreds of km away for one timestep. These are filtered from distance calculations (steps > 50 m/s excluded) but the erroneous point may still be visible on the map.
24-hour gaps: Two Fridtjof missions (133914, 172120) span two calendar days with a 24-hour gap. They are split into separate segments in the Excel export and the gap is excluded from duration calculations.
Mission status — Marie: lauv-marie logs use IMC v5.5 (0xFE55 sync). VehicleState is not parsed from IMC6 by the current pipeline, so classification uses depth data only.
Depth filter for distance: "Sailed distance (depth > 1 m)" counts only steps where the current point has depth > 1 m and the time to the next point is ≤ 30 s. Yo-yo dives with long step intervals may be under-counted.
Sensor data: Not all sensors are recorded in every mission. Missing values appear as NULL in the database. The sensor availability table in the dashboard is hardcoded from the IMC message analysis (imc_meldingar.xlsx) and may not reflect per-mission sensor failures.
vessel_transit heuristic: Points with speed > 2.5 m/s are assumed to be vessel transit. LAUV maximum speed is ~2 m/s, so this threshold should be safe, but occasionally a fast dive or current may be misclassified.

Examples of useful queries

All missions in Isfjorden, 2022

In the map: draw a rectangle over Isfjorden, set year filter to 2022, click Søk.

Which Fridtjof missions had technical failures?

Open the Farkoster tab → Fridtjof → Mission status: ❌ Technical shows 43 missions. The Excel file (alle_missions.xlsx) has a "Mission-status" column with the error reason in the Merknad column.

Direct PostGIS query — missions deeper than 80 m

SELECT DISTINCT name, vehicle, MAX(depth) FROM auv_tracks WHERE depth > 80 GROUP BY name, vehicle ORDER BY MAX(depth) DESC;

Total km per campaign

SELECT campaign, vehicle, round(SUM(ST_Distance(geom::geography, lag_geom::geography))/1000, 1) AS km FROM (...) GROUP BY campaign, vehicle;

Use the auv_tracks table with a LAG window function. The track_km_by_vehicle_year materialized view already does this per vehicle × year.

Which year had the most dive time?

Dashboard → Oversikt → Sailed distance per year chart. Hover each bar for the value.

Download all tracks for a specific campaign

GET /geoserver/NTNU/wfs?SERVICE=WFS&VERSION=2.0.0&REQUEST=GetFeature&TYPENAMES=NTNU:auv_fridtjof&CQL_FILTER=campaign='sss_bjorn'&outputFormat=application/json
